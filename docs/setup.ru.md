# Attendance · Vistula

Личный Telegram Mini App: предметы и отдельные формы занятий, календарь плиток, быстрая кисть, серверные расчёты, iCalendar, экспорт/восстановление. Рабочая база изначально пустая. Демо включается только отдельной командой и использует другую базу.

## Быстрый запуск в Telegram через временный HTTPS-туннель

После заполнения BOT_TOKEN и OWNER_TELEGRAM_ID **в игнорируемом `.env`**:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\telegram.ps1
```

Скрипт проверяет бота, скачивает официальный cloudflared с проверкой SHA-256, создаёт временный HTTPS-адрес, сохраняет PUBLIC_APP_URL в `.env`, применяет миграции и запускает приложение, туннель и polling-бота в фоне. DEV_AUTH_BYPASS выключен, APP_ENV=production. Бот получает меню Attendance; отправьте ему `/start`, чтобы открыть Mini App. Используется рабочая база `backend/data/attendance.db`, без demo seed.

Компьютер и туннель должны оставаться включёнными. При новом запуске HTTPS-адрес меняется, меню обновляется автоматически. Этот вариант предназначен для временного использования; [описание Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/). Логи и состояния процессов находятся в игнорируемой `.runtime/`. Остановка сохраняет БД:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\telegram-stop.ps1
```

После остановки можно повторно выполнить `telegram.ps1`. Он не завершает чужие процессы и отказывается запускаться, если порт 8000 занят.

## Локальный запуск (Windows PowerShell)

Нужны Python 3.12+ и Node.js 22+ (проверено на 3.12 и 24). В корне проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.lock.txt
Copy-Item .env.example .env
cd frontend
npm.cmd ci
npm.cmd run build
cd ..
.\scripts\dev.ps1
```

Открыть http://127.0.0.1:8000. Скрипт явно включает DEV_AUTH_BYPASS только для локального запуска; виден баннер. Если PowerShell запрещает запуск локального скрипта: `powershell -ExecutionPolicy Bypass -File .\scripts\dev.ps1` (на один процесс).

Linux/macOS:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.lock.txt
cp .env.example .env
cd frontend && npm ci && npm run build && cd ../backend
../.venv/bin/python -m alembic upgrade head
DEV_AUTH_BYPASS=true ../.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

Для hot reload отдельно запустить backend на 8000 и `npm run dev` из frontend (5173, API proxy). Production использует собранный frontend и API на одном origin.

## Первый ввод

1. Настройки → новый семестр: реальные границы, а не диапазон upcoming.
2. Импортировать `.ics`, проверить предпросмотр. Либо создать предмет и тип, затем занятия вручную.
3. В предмете → карандаш: выбрать требование, полный объём и подтвердить полноту только при наличии всей истории.
4. «Быстрая отметка» → кисть → прошедшие плитки. Повторный выбор того же статуса ничего не переключает. Undo сохраняется сервером.

## Календарь, общий список и быстрый разбор истории

В «Сегодня» доступны три вида: день, календарь по месяцам и общий список всех предметов. Нажмите «Неотмеченные» (или счётчик на обзоре), чтобы разбирать прошлые пары подряд, без открытия компонентов. Поиск учитывает предмет, тип и аудиторию. Кнопки «Был» / «Пропустил» доступны прямо в строке; текущую отметку можно очистить.

В календаре выберите день: на телефоне экран сразу прокрутится к его занятиям. «К месяцу» возвращает к сетке. Точки и числа показывают записи дня, а не проценты выполнения требования. Дата, на которой есть неотмеченные пары, выделена. Детали занятия открываются поверх календаря/списка, сохраняя контекст.

Отметьте несколько строк флажками или нажмите «Выбрать все», затем примените один статус. Группа сохраняется атомарно; «Отменить» откатывает всю последнюю группу. Будущие и отменённые пары не выбираются для фактической отметки.

На обзоре панель «Посещения и пропуски» показывает количество посещённых, пропущенных и неотмеченных **занятий** и их динамику по неделям: последние 30 дней либо вся сохранённая история. Это описание известных записей, а не общий процент выполнения требований курсов. Отмены и будущие пары исключены; неотмеченные не считаются пропусками. Агрегаты рассчитываются backend и пересчитываются после отметки/undo.

Для обновления только backend при работающем временном туннеле: `powershell -ExecutionPolicy Bypass -File .\scripts\restart-app.ps1`. Скрипт делает SQLite backup и сохраняет прежний HTTPS-адрес, бот и данные.

Запишите приватную ссылку **самостоятельно в игнорируемый `.env`** как `USOS_ICAL_URL=...` либо в переменную окружения. Она должна вести на `https://usosapps.vistula.edu.pl/services/tt/upcoming_ical` с вашими параметрами. Не отправляйте её в чат и не коммитьте. После изменения окружения перезапустите backend → «Обновить USOS сейчас» → предпросмотр → сохранить. Количество upcoming-событий не является полным объёмом семестра.

Если лента не даёт `X-USOS-GROUP-ID` / `X-USOS-CYCLE-ID`, приложение не угадывает группы по названиям: отдельные UID получают отдельные компоненты. Чтобы собрать реальные занятия в один компонент, предварительно создайте его и выберите в предпросмотре для соответствующих событий. Точный формат настоящего USOS-файла пока не проверен: исходные SUMMARY сохраняются, суффикс после `: ` используется как необъяснённый код, иначе показывается `?`. В UI можно исправить код и отображаемое название. Это сознательная безопасная граница до получения реального файла.

## Технические решения

- React + TypeScript + Vite, Tailwind CSS 4 и собственные небольшие компоненты; FastAPI, SQLAlchemy 2, Alembic, SQLite/WAL. Прямые зависимости зафиксированы, Python транзитивные — `requirements.lock.txt`, npm — `package-lock.json`.
- Сервер — единственный источник формул и состояния. `calculate()` использует Decimal/ceil; UI не дублирует расчёты. Завершённость пары определяется по окончанию в UTC, день отображается в Europe/Warsaw. В часовом режиме нужны явно заданные целые академические единицы; длительность не делится на 45.
- Будущие/текущие пары нельзя отмечать посещёнными или пропущенными. Отмены сохраняют отметки и историю, исключаются из автоматического объёма. Ручной N после отмены не уменьшается.
- Версии защищают CRUD и attendance от потерянных обновлений; пачка отметок и undo — транзакции. `request_id` делает повтор запроса отметки безопасным. UI последовательно отправляет быстрые действия, откатывает оптимистичные плитки при ошибке, предлагает повтор и игнорирует устаревшие GET-ответы. Сводка обновляется после подтверждения записи, а также раз в минуту.
- JSON экспорт включает исходные поля и overrides, но не auth-сессии/секреты. История undo хранится в SQLite; JSON-восстановление сбрасывает старые undo. Удаление компонента/курса разрешено только без дочерних данных; занятия отменяются вместо разрушительного удаления истории.
- `icalendar` + `recurring-ical-events` обрабатывают folding, escape, RRULE, EXDATE, исключения и зоны. Импорт ограничен семестром, 2 МБ, 5000 событий и DAILY или реже. All-day пропускаются с предупреждением. Ключ: source + UID + occurrence; перенос одиночного UID сохраняет attendance. Исчезновение из upcoming ничего не удаляет. Обновление импортированного занятия оставляет личные overrides, которые можно сбросить.
- Импорт и USOS проходят предпросмотр (30 минут); изменения данных после preview требуют повторного preview. Неоднозначный новый UID требует явного сопоставления, пропуска или создания отдельно. USOS HTTPS host/path ограничены, redirects выключены, proxy из окружения не используется, DNS проверяется на глобальные адреса; соединение привязано к проверенному IP с исходным TLS SNI/проверкой сертификата, без повторного DNS-разрешения. Загрузка имеет лимит и таймаут.
- Один web worker, один сервер. Mutex сериализует записи и синхронизацию; SQLite обеспечивает транзакции. Фоновое обновление необязательно и в этой версии не включено; только ручной запуск.

## Telegram и доступ

Официальные источники, сверенные при реализации: [Mini Apps / initData validation](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app), [WebApp API](https://core.telegram.org/bots/webapps), [InlineKeyboardButton](https://core.telegram.org/bots/api#inlinekeyboardbutton).

Backend проверяет HMAC-SHA256 (WebAppData), все поля кроме hash, auth_date (5 минут + 30 секунд погрешности), числовой OWNER_TELEGRAM_ID. `initDataUnsafe` не используется. Затем выдаётся случайный bearer-токен на час; в SQLite хранится только SHA-256 токена. Токен находится в памяти frontend, не в localStorage/cookie. Cookie-аутентификация не используется: ambient credentials отсутствуют, CSRF через cookie неприменим; CORS допускает только PUBLIC_APP_URL. По истечении сессии приложение следует переоткрыть через бота.

Production запрещает DEV_AUTH_BYPASS и требует BOT_TOKEN, OWNER_TELEGRAM_ID, HTTPS PUBLIC_APP_URL. Отсутствие валидной авторизации закрывает все API, включая экспорт/импорт/настройки. Скрипт бота отвечает только владельцу в private chat, `/start` отправляет inline Web App кнопку. SDK подключён с telegram.org; используются тема, safe area, viewport и BackButton. Реальная проверка внутри Telegram требует ваших секретов и HTTPS.

1. В @BotFather: `/newbot`, получить токен, записать в `.env` как BOT_TOKEN.
2. Записать свой Telegram numeric ID в OWNER_TELEGRAM_ID. Это не username и не USOS user_id.
3. Выбрать хост/домен, настроить HTTPS reverse proxy и PUBLIC_APP_URL.
4. В BotFather `/mybots` → бот → Bot Settings → Configure Mini App; задать HTTPS URL. При желании настроить Menu Button на тот же URL.
5. Запустить бот: из backend `..\.venv\Scripts\python.exe -m app.bot`, либо Compose профиль ниже. У бота должен быть один polling-процесс; ранее настроенный webhook нужно отключить перед polling.
6. Отправить своему боту `/start`, открыть кнопку. Владелец проходит проверку; чужой ID получает отказ.

Не включайте debug-логирование HTTPX/Telegram. Access log Uvicorn отключён в командах запуска. Обработчики ошибок не возвращают исходные секретные URL/initData.

## Deployment: один сервер

Скопировать `.env.example` в `.env`, задать реальные production значения. Затем:

```sh
docker compose --profile telegram up -d --build
```

SQLite и автоматические backups находятся в named volume `attendance-data:/data`. Порт 8000 слушает только loopback хоста; reverse proxy (например Caddy/Nginx) завершает HTTPS и проксирует весь origin на 127.0.0.1:8000. Задайте лимит тела 10 МБ и разумный rate limit. Не запускайте несколько workers/реплик. Команда `docker compose down` сохраняет volume; **не используйте `down -v`**, если хотите сохранить историю. Не храните SQLite на временном диске или сетевой FS.

Пример Caddyfile (заменить домен):

```caddy
attendance.example.org {
    request_body { max_size 10MB }
    reverse_proxy 127.0.0.1:8000
}
```

Покупка хостинга и публикация не выполнялись. Docker-сборка требует Docker и сети; если Docker недоступен, это отдельно отмечено в результатах проверки.

## Резервирование

Настройки → экспорт JSON: переносимая копия без секретов. Восстановление сначала валидирует схему и ссылки, показывает количество записей, затем требует явного нажатия «Подтверждаю замену данных». Перед заменой используется `sqlite3.Connection.backup()`, не копирование активного WAL-файла. Копии находятся рядом с БД в `backups/`. Кнопка серверной копии делает такую же согласованную копию.

Храните копии отдельно от сервера (например, 7 дневных + 4 недельных); автоматическая внешняя доставка не настроена. Для аварийного восстановления SQLite остановите app, сохраните текущие файлы БД/WAL/SHM, замените БД согласованным `.sqlite3` backup и уберите старые WAL/SHM из активного пути, затем запустите app с миграциями. Не подменяйте работающую БД.
